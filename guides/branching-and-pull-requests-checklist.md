# Branching and Pull Requests Checklist

Paste this into your own notes, or post it in the community as a comment when you're done. Tick
each line as you complete it. Full instructions for any step are in the written guide,
`branching-and-pull-requests-written-guide.md`.

```
[ ] I know the rule: I never push to the community repo, only to my own repo or the practice repo.
[ ] I have my own practice repo, and I made a branch on it before touching anything.
[ ] I saved my change on that branch, opened a pull request, and merged it (squash and merge, our
    pick).
[ ] I hit the planted conflict on purpose, resolved the simple case, clicked Commit merge to
    actually close it out, and know the line "this one needs a person, not me" for anything
    bigger.
[ ] I forked the practice repo, made a change on my fork, and opened a pull request back to it.
[ ] I know a maintainer merges that one, not me, and I only ticked "Allow edits from maintainers"
    because this repo has no workflows and no secrets.
[ ] I posted the URL of my merged pull request in the community.
```
